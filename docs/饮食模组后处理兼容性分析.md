# 饮食模组后处理兼容性分析

分析基于 `6963b33`。已复现的兼容性问题发生在资源加载阶段。饮食模组和光影包同时提供 `graphics_settings/post_process.json` 时，引擎取优先级更高的一份完整配置。即使饮食模组的四个疾病效果都处于关闭状态，另一份配置中的效果仍会从队列中消失。

## 共享配置覆盖

[项目的后处理配置](../resource_pack_qewqRv3q/graphics_settings/post_process.json#L2) 同时提供全局 `render_order` 和 `process_array`。前九项和本机网易开发包 3.8.0.313307、3.9.0.401155、3.10.0.420447 的 `vanilla_netease/graphics_settings/post_process.json` 逐项一致，包括默认开启的 Bloom。后四项分别是便秘波纹、发烧渐晕、低血糖重影和佝偻病骨折。这个配置从提交 `7eb8135` 起随资源包加载，当时低血糖从控制内置高斯模糊切换到了独立的自定义效果。

网易文档将 `render_order` 定义为渲染顺序，将各项的 `enable` 定义为默认启用状态。当前 [客户端脚本](../behavior_pack_XFwwevzL/Diet_NullGr/ModSys/Disease/Disease_cs.py#L154) 只按饮食模组自己的名称设参和启停。关闭疾病总开关会清理疾病状态和演出，资源包仍会提供这份公共配置。[后处理配置文档](https://mcwiki.easecation.net/mcguide/16-%E7%BE%8E%E6%9C%AF/7-%E6%9D%90%E8%B4%A8%E4%B8%8E%E7%9D%80%E8%89%B2%E5%99%A8/4-%E6%9D%90%E8%B4%A8%E5%AE%9E%E6%88%98.html#%E8%87%AA%E5%AE%9A%E4%B9%89%E5%90%8E%E5%A4%84%E7%90%86)

### 双包对照

在网易 PC 开发包 3.9.0.401155、RenderDragon D3D12 的隔离存档中，使用饮食模组的效果名称和顺序，搭配一份含有独有效果 `dietAuditOtherPack` 的测试光影配置。初次加载和纯原版资源对照都出现 `threashold_pick` 材质解析断言。后续对照保留各自的 `render_order`，将所有效果设为禁用并清空 `pass_array`，以单独观测配置加载。

| 存档资源包顺序 | `GetPostProcessOrder()` 返回的内容 |
| --- | --- |
| 饮食模组在前，测试光影在后 | 九个内置效果和四个饮食效果，共 13 项 |
| 测试光影在前，饮食模组在后 | 九个内置效果和 `dietAuditOtherPack`，共 10 项 |

在第二种顺序下，给缺失的 `dietFeverHeat` 调用 `SetParameter` 和 `SetEnableByName` 都返回 `False`。当前脚本忽略返回值，仍会把持有标记设为 `True`。患病期间查到效果仍未开启时会在客户端 Tick 上继续尝试。两种顺序下，用 `AddPostProcess` 追加一个禁用且没有渲染 pass 的测试项均成功，原有顺序保留。[客户端启停逻辑](../behavior_pack_XFwwevzL/Diet_NullGr/ModSys/Disease/Disease_cs.py#L187) · [ModAPI 后处理接口](https://mcwiki.easecation.net/mcdocs/1-ModAPI/%E6%8E%A5%E5%8F%A3/%E5%90%8E%E5%A4%84%E7%90%86/%E8%87%AA%E5%AE%9A%E4%B9%89.html)

## 材质与画面叠加风险

- **材质文件也使用公共路径。** 本包的 `materials/postprocess.material` 只定义四个 `diet*Mat`。本机 3.10.0.420447 的原版同路径文件有 17 个材质，其中 14 个仍被本包的后处理配置引用，包括 Bloom 的 `threashold_pick` 和 `daul_blur_*`。效果名、材质名和着色器名的前缀可以降低标识符重名概率。材质定义能否跨包合并仍需按目标渲染后端验证，双包实验只确认了后处理 JSON 的选择行为。[项目材质](../resource_pack_qewqRv3q/materials/postprocess.material) · [材质加载文档](https://mcwiki.easecation.net/mcguide/16-%E7%BE%8E%E6%9C%AF/7-%E6%9D%90%E8%B4%A8%E4%B8%8E%E7%9D%80%E8%89%B2%E5%99%A8/3-%E6%9D%90%E8%B4%A8%E9%85%8D%E7%BD%AE%E8%AF%B4%E6%98%8E.html#%E6%9D%90%E8%B4%A8%E6%96%87%E4%BB%B6%E7%9A%84%E5%8A%A0%E8%BD%BD)
- **发作时会再次处理整屏颜色。** 四个疾病效果各跑一个全分辨率 pass。便秘改变场景取样位置，发烧叠加暖色和渐晕，低血糖每像素采样场景七次并加入重影和黑边，骨折会叠加白闪、灰度和缩放。多个效果同时运行时，光影的清晰度、亮度或色彩可能被后续处理改变。全屏采样也会叠加 GPU 开销，实际帧率影响需要实测。[发烧着色器](../resource_pack_qewqRv3q/shaders/glsl/diet_fever_heat.fragment#L31) · [低血糖着色器](../resource_pack_qewqRv3q/shaders/glsl/diet_hypoglycemia_vision.fragment#L49) · [骨折着色器](../resource_pack_qewqRv3q/shaders/glsl/diet_rickets_fracture_impact_composite.fragment#L25)
- **不同渲染后端需要各自验证。** 项目提供的是 GLSL 与 `.material`。本机网易开发包同时包含 `post_process_rngl.json`，其中 Bloom 引用的材质名带 `.rngl`。这次只验证了 PC RenderDragon 的配置加载和 API 行为。玩家反馈中的具体光影包、移动端和实际疾病着色器的合成效果尚待验证。

## 修复方向

优先让基础包退出全局后处理配置。发烧暗角、低血糖黑边、骨折闪白可由客户端 UI 叠层表达，音效可继续提供症状反馈。场景波纹、模糊和重影需要采样游戏画面，可以作为兼容设备上的可选效果。

保留全屏着色器时，验证材质能否通过独立资源注册，再按需调用 `AddPostProcess` 动态追加本模组的过程。用 `GetPostProcessOrder` 核对注册和重载后的顺序，并依据注册、设参、启停的返回值更新本地状态。文档注明调用 `AddPostProcess` 会启动后处理，因此应在允许启用屏幕特效且确实需要时调用。动态追加的实测只覆盖了队列行为，材质注册和实际渲染仍需单独验收。[AddPostProcess 接口](https://mcwiki.easecation.net/mcdocs/1-ModAPI/%E6%8E%A5%E5%8F%A3/%E5%90%8E%E5%A4%84%E7%90%86/%E8%87%AA%E5%AE%9A%E4%B9%89.html#addpostprocess)

用玩家反馈中的具体光影包验收时，比较光影单独加载、双包正序、双包逆序三组结果。进世界且没有疾病时检查光影队列和画面，再触发疾病并检查痊愈后的恢复，最后重进存档验证资源重载。
